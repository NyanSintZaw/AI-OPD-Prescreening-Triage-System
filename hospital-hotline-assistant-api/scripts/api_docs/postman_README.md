# Postman collections

Generated by `hospital-hotline-assistant-api/scripts/api_docs/generate.py` from
the FastAPI apps' own OpenAPI definitions — never hand-edited. **Collection
v2.1 JSON**: in Postman desktop, File → Import → drop this folder.

| File | What |
|---|---|
| `AI OPD Prescreening API.postman_collection.json` | our whole backend, folders by URL prefix; `POST /admin/login` captures `token`, `POST /sessions` captures `session_id` |
| `HIS Integration (Data Requirements V1).postman_collection.json` | **the one to review with hospital IT** — what we call on the HIS (`/api/v1/*`, implemented by `hospital-his-mock`). Anything beyond the hospital's Data Requirements V1 is tagged **MFU extension** in the request description. The two write-back bodies are produced by the real SBAR / vitals builders |
| `Mock HIS (demo only).postman_collection.json` | the mock's `/api/*` demo scaffolding (seeded visits, vitals push, reset) — absent at go-live |
| `AI Model (local inference).postman_collection.json` | every call the backend makes to the AI workstation (LLM chat completions, STT, TTS) with the exact prompt bodies. Contract: `docs/ai-model-io.md` |
| `local.postman_environment.json` | localhost URLs, seeded nurse login, demo HIS tokens |
| `hospital.postman_environment.json` | placeholders only — fill in on site, never commit secrets |

Regenerate after any route/schema/prompt change:

```bash
cd hospital-hotline-assistant-api && uv run python scripts/api_docs/generate.py
```

No Postman CLI needed; runs in-process in a few seconds.
