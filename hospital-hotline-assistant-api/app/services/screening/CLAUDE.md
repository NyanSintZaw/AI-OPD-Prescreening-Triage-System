# AI screening engine (LangGraph, deterministic)

- Core rule: LLM only extracts findings / phrases questions & explanations. Worked turn-by-turn example with real artifacts: `docs/screening-flow-walkthrough.md`. Pure rules (`rules/`: `red_flags.py`, `disposition.py`, `department_map.py`, `question_policy.py`) decide the 5-level triage + department from versioned criteria. Never let the LLM decide a level.
- One chat turn = one bounded graph run (`graph.py`, nodes in `nodes/`): ingest (LLM extraction) → red-flag + completeness gates (pure) → question or dispose → explain (validated). State = JSONB in `screening_sessions` via `persistence.py` — deliberately NO LangGraph checkpointer.
- Plausibility bounds: every incoming number (spoken, typed, cuff) passes `check_vitals()` in `vitals.py` against the criteria's `vital_bounds`. Impossible → dropped before the rules + re-asked once, then skipped; shown flagged (not blank) in nurse review; never sent to HIS. Bounds are an input filter, NEVER a triage threshold — 250/130 must stay acceptable. See `docs/vital-bounds.md`.
- Confirm-before-fire: a level-1/2 disposition NEVER fires from free-text extraction alone. `Finding.confirmed` = answered its question / HIS record / instrument; the gate in `graph.route_after_ingest` re-evaluates on confirmed-only findings (vitals always count) and asks the driving findings' verbatim confirm questions (`confirm_question_for`) instead of disposing. Two non-answers accept the extraction (fail-safe over-triage). Extraction also returns `evidence` — the verbatim patient quote, containment-verified in ingest, shown in the trace.
- Criteria: `app/data/screening_criteria.json` (bilingual, condition AST in `rules/criteria_models.py`), seeded by `scripts/seed_screening_criteria.py` as version 1 active; sessions pin their version. Criteria-upload flow was removed.
- `engine.py` (`make_triage_engine`) implements the `TriageEngine` protocol so TriageService/SSE/frontend contracts stay fixed. Objective inputs (HIS age, cuff vitals) enter via `run_turn(turn_context=...)` and merge BEFORE the red-flag gate.
- **No patient identifier ever reaches the model** — no name, HN, VN, slip code, session id or birthdate. The explanation asks for a `[NAME]` placeholder and substitutes the real name after the reply comes back; the identity gate does not take a name at all. Guarded by `tests/screening/test_no_pii_in_prompts.py`. Exact payloads: `docs/ai-model-io.md` (generated).
- LLM access only through `model_adapter.py` (`ChatGoogleGenerativeAI` vertexai, gemini-3.1-flash-lite, thinking minimal; `openai_compatible` for local models). Always use `ainvoke_with_timeout`; Gemini 3 needs `response.text` not `.content`. Ingest normalizes near-miss category ids the model invents.
- Every LLM call + rules decision audits to `ai_inference_audit`. Replies validated by `validator.py` in th AND en — no level/color/diagnosis leaks.
- `voice_bridge.py` (`TurnVoiceService`) is the only voice service; it reuses `process_chat_stream` per turn.
- Tests: `tests/screening/` — table-driven rules tests from seed criteria, `FakeChatModel` graph tests, golden transcripts validator-checked in both languages. Extraction quality: `scripts/run_extraction_eval.py` over `evals/extraction_phrases.json` (single-utterance, real LLM, per-finding recall/over-match **plus `expect_absent` — a dropped denial is what makes the interview re-ask, see `docs/ai-quality-evaluation.md`**) — run it after touching the extraction prompt, catalog vocabulary, or finding synonyms.
- **Voice layer (2026-08-20, rewording 2026-08-23):** every question is rendered by ONE structured call in `nodes/question.py` (`PhrasedQuestion{ack, question, options}`) with the persona from `app/data/persona_default.json` (`persona.py`) and the last two exchanges (`state.recent_turns`, appended in `engine._execute`). Every kind except `measurement` may be reworded — but a red-flag / scale / confirm rewording is used only when `wording_violations()` is empty: it must still name every symptom the template names (English stems / Thai cores with distinctive-mark logic, `_marks`), keep the 0–10 scale, stay yes/no when the template is yes/no, ask exactly one question, and pass the validator; otherwise the template goes out verbatim and the audit says why (`paraphrase_rejected`). The prompt hands the model the words to keep (`keep_terms_line`; severity-grade siblings like severe respiratory distress are NOT listed). Chips for red-flag/scale/confirm stay deterministic (ids are the answer mapping); only slot/associated may take model-authored chips. Confirm questions use the catalog's authored `confirm_en/th` (criteria v5) before the label-in-a-sentence fallback. Review sheet: `scripts/review_question_wording.py` → `evals/reports/question-wording-*.md` (th 225/235, en 220/235 accepted on 2026-08-22); guard tests in `tests/screening/test_wording_guard.py`. `clean_ack` drops any ack carrying a question marker or a validator leak.
- **RAG in explain:** `GraphDeps.rag_search` is `search_triage_manual_status(query, language)`; passages inject only when `available`; the audit entry carries `rag: {used, reason, hits, chars, latency_ms}` (→ `rules_trace`, `/trace`, nurse review, `/admin/ai-metrics.grounding`). Emergency explanations never use RAG.
- **SpO2:** asked via the universal `uq_spo2` measurement question, gated on a confirmed `dyspnea` finding; `dc_retraction` makes the MOPH 90–94% band reachable. Spoken home-oximeter numbers arrive as `ExtractionResult.spo2_percent` (bounds-checked like temperature).
- **Corrections (2026-08-22):** the engine is a belief state — findings/slots/vitals/age re-merge every turn, last write wins, rules re-decide. What moves on a restatement: the category (specific→specific only when the current template's `anchor_finding_ids` were retracted this turn, or the chief complaint was restated AND the new anchor is present — `ingest._apply_category`; old ones in `state.complaint_history`), the chief complaint, `slots.severity` (follows the score), and a second complaint's red flags (`question_policy._secondary_red_flags`, after the template's own). A retracted *confirmed* critical finding gets its verbatim confirm once (`state.pending_retraction` → `graph`), the mirror of confirm-before-fire. What never moves: device readings (speech never overrides), HIS gender, and a made disposition — post-disposition speech is recorded into `patient_follow_up` by the repeat node, not re-triaged. `generic` still upgrades to the first specific category; the self-harm screen lives only in `mental_health`. Tests: `tests/screening/test_corrections.py`; eval cases `corr_*`.
- **Criteria-based E2E:** `tests/screening/test_e2e_vignettes.py` (offline, `present_feeder`) and `test_e2e_vignettes_live.py` (integration, real model, writes `evals/reports/`). Vignettes support `utterances`, `must_not_ask`, `department_name_*`, `oracle`.
